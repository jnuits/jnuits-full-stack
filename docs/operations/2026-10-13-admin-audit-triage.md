# Admin panel audit: validated findings and repair decisions

Status: repair scope approved by the owner on 2026-10-13; implementation in progress.

Reviewed at `59152c0ae4afcf830b45a6b8828db1382d1bcdf9` on 2026-10-13. Source: the owner-supplied Gemini handover titled “Admin Panel Normalization, Security Hardening & Workflow Consolidation.” Its findings and implementation instructions are external proposals, not proof or authorization to replace existing policies.

## Intent and constraints

Fix verified defects, reduce operator confusion and duplication, and preserve every functioning capability. Keep JnUITS styling, native selects, canonical department options and the released control-height fixes. Public forms and authentication keep Turnstile; authenticated dashboards remain CAPTCHA-free. Keep session/lifecycle/origin/rate-limit protection, native password verification, and native AAL2 plus password and exact session/intent-bound proof for admin-role changes. Routine membership operations retain optional MFA enforcement. No real account, password, role, request or mail mutation is permitted merely for testing.

## Decisions against every handover section

| Handover | Evidence in the current implementation | Decision |
| --- | --- | --- |
| 1.1 CMS authorization | `src/app/admin/layout.tsx` already resolves route permissions from a proxy-overwritten return-path header. `src/lib/admin/access.ts` and CMS actions use distinct `cms.*` permissions. `admin.content.manage` is absent. Several pages still rely on the layout before service-role reads; installed Next.js authentication guidance says layouts do not guarantee authorization of nested rendering or navigation. | Add the existing, correct permission check at each relevant page/data-read entry point. Keep action-level checks and granular CMS roles. Do not describe this as a verified public breach or introduce a blanket permission. |
| 1.2 Workplace, decisions, reconciliation | Actual permissions are respectively `admin.membership.manage`, `admin.decisions.read`, and `admin.reconcile.manage`. Reports use `admin.reports.read`. | Add checks before privileged reads using these exact permissions. Reject the report’s incorrect permission substitutions. Apply the same rule to other uncovered admin reader pages found during this scoped inventory. |
| 1.3 Self-profile and account management | Admin Accounts navigation is currently unrestricted; `/admin/settings/profile` redirects into it. `loadAdminProfileDirectory` reads the entire admin directory even for a self view. | Give every active admin a clearly named My Profile route with self-scoped reads. Gate account-management navigation and non-self directory views with `admin.admin_profiles.manage`. Preserve the legacy self bookmark and role-management safeguards. A self-view query must never authorize another account’s data or management actions. |
| 2.1 Project editor | The `projects` table and `ProjectSummary` have neither `sort_order` nor `media_asset_id`. They store `cover_image_url`, category, tagline, dates and featured state. The editor submits ignored fields, omits accepted fields, and offers draft/published statuses although the database accepts active/completed/archived. `updateProject` currently writes absent optional values, including a null cover. | Repair the complete form/action contract rather than binding nonexistent properties. Preserve actual existing values on ordinary edits, use real statuses, remove nonfunctional project controls, keep stable existing slugs, and key editors by record. Developer profiles retain their genuine media ID and sort order; preserve zero using nullish defaults. No new columns or migration are justified. |
| 2.2 Advisor actions and raw Auth ID | All three menu entries open the profile tab. The actual public section is `#advisor-board`, with a separate `#former-advisors` section. The profile action currently accepts and writes a posted `userId`. | Open the appropriate Profile or Access tab; use a real public link where published. Remove the editable raw Auth UUID from profile presentation. Profile saves must preserve the server-loaded existing link; creation/linking continues through the existing email-based Access workflow. Keep tenure, visibility, departments, avatar and all other fields. |
| 2.3 Sidebar badges | The two obsolete queries are conditional and currently do not execute because no navigation entry consumes their badge keys. The reported three queries on every load is inaccurate. The active badge includes workplace updates, but the identity queue excludes them. | Remove obsolete types/branches and share the exact identity request-type set between queue and badge. Fail closed on count errors rather than claiming zero. Keep links/counts for separately handled requests; do not count account deletions as identity requests while they are reviewed elsewhere. |
| 3.1 Unified moderation routes | Identity changes, legacy workplace requests, account deletion and decision history use different review contracts and, for history, a distinct read permission. Current approved policy lets ordinary workplace information save directly after password unlock. | Keep the working routes, filters and actions. Improve accurate labels and discoverability rather than rebuild all queues or reinstate workplace moderation. Identity badge must describe the queue it opens. Existing legacy workplace and account-deletion review controls remain reachable. |
| 3.2 One combined member save | Profile edits use `expectedUpdatedAt` conflict protection; operational/role changes use separate validation, capabilities and confirmation. A sequential combined save is not atomic and can report failure after a partial mutation. | Preserve separate saves and their explicit effects. Do not add a misleading combined action, weaken verification or introduce a database transaction solely for cosmetic consolidation. Keep the responsive drawer and unsaved-edit protection. |
| 3.3 Reports/reconciliation | Both consume `buildOperationalSnapshot`, but have different route permissions and views. Reports show multiple report types; reconciliation diagnoses parity and cutover readiness. | Preserve both routes and the already shared snapshot loader. Do not redirect a reconciliation-authorized operator into a reports-permission denial or widen either role. Permission-aware links can improve discovery. |
| 3.4 Bulk operations and certificates | `BULK_OPERATION_TYPES` includes lifecycle updates, role updates, alumni conversion, account-deletion review and invitations as well as legacy imports. Shared Intake drafts do not replace these verified operations. Certificate creation already validates Event/Exam/Course; legacy correction remains useful. | Keep all bulk capabilities, preview/commit/audit history and permission boundaries. Add a clearly permission-scoped link to validated member/committee Intake for new records where appropriate. Do not remove the bulk workflow or recategorize issued certificates. No new certificate enum is required. |
| 4.1 Singleton bodies and hub links | `saveContentPage` replaces body JSON. The Home editor constructs only a subset of fields and drops slider/stat keys. About already passes through its body and links its dedicated editor, so the claimed identical About bug is overstated. Changing the local slug can reuse another page’s state. | Preserve server-owned/unedited structured keys; update only the editor’s owned fields. Use revision conflict checks to avoid stale overwrite, reject malformed bodies, and load a fresh keyed editor when selecting a singleton. Keep intentional clear operations for edited fields. Add permission-aware hub links for About, Slider, Form Studio and Contact Settings. |
| 4.2 Media | Projects’ current media select cannot save their actual cover field. Media registration is a working fallback to the primary upload flow. Shared pickers have distinct output names/endpoints. | Reuse the visual media primitive with a compatible project cover adapter and permission-gated upload. Preserve legacy cover URLs even when absent from the current media page. Put manual registration in an Advanced disclosure without removing any field or action. Do not substitute the events picker endpoint and thereby require unrelated event permissions. |
| 4.3 Audit actors | Audit filtering accepts a UUID, while events already reference actor IDs. The audit permission does not imply unrestricted account-management permission. | Provide a bounded actor-name selector with only a minimal authorized projection. Keep existing query/export parameters and custom/legacy actor UUID values. Do not expose the full admin/member directory merely to build options. |
