# Private profile completeness
Rubric version 1 is advisory and computed from canonical owned data on the server. It grants no permission and never blocks a partial save. Pending requests and failed uploads earn no points.

Current members have nine equal checks; alumni have eight: name, canonical JnUITS ID, verified linked Auth email, recognized department, valid batch, persisted photo, phone, and workplace. University student ID is the ninth check for current members. Existing normalized batch/department and Bangladesh phone formats are accepted without rewriting stored data. Phone format is not proof of ownership.

Workplace is one check requiring organization, designation and location. A password-unlocked explicit not-applicable declaration excludes that check only when all three fields are blank. Unanswered is incomplete. No privacy or employment status implies this declaration. Contradictions fail atomically; the editor offers an explicit local clear before Save. All workplace writers preserve consistency, including legacy reviews. Social links and graduation year remain optional and unscored.

An admin's own profile has only three checks: display name, verified Auth email and persisted photo. Its member/alumni record, where present, keeps a separate rubric. Missing links are not fabricated as 0%; unavailable source evidence produces unavailable guidance. Protected values never enter next-step DTOs, and the existing password gate controls field rendering.

MFA guidance describes existing permissions. Enrollment alone does not establish native AAL2. Admin role invitation/change/removal still requires native AAL2, current-password verification and exact session/intent-bound proof. Optional routine review enforcement, legacy unknown enrollment, and the seven-day reminder snooze are preserved.

Apply the forward workplace-applicability migration before enabling its editor contract. Historical SQL is unchanged. Rolling back application code preserves declarations; the database accepts the old allowlisted payloads. There is no production backfill or automatic private/public change.

Release evidence and remaining gates are recorded in the ignored release ledger. Standalone frontend screenshots are fixtures, not production acceptance.
