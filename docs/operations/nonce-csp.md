# Nonce CSP operations and validation

Every HTML document receives a fresh 192-bit random nonce. Proxy overwrites incoming x-nonce and request CSP, passes the matching policy to Next.js rendering, and sets the response policy. Production script-src has nonce and strict-dynamic without unsafe-inline or unsafe-eval. Development alone permits unsafe-eval. The existing style policy and required Cloudflare, Supabase, Cloudinary, Sentry and frame origins are preserved, along with HSTS and the other static security headers.

HTML is dynamic and private/no-store so a document nonce cannot be shared or reused. Next.js automatically nonces framework and inline bootstrap scripts from request CSP. The async root layout supplies the nonce to the application provider and both Turnstile consumers. Existing request-scoped React data memoization remains; the bounded blog/notice loaders avoid whole-body archive queries. No private or session-bound response was moved into a shared cache.

The Auth proxy still runs for API/navigation/prefetch traffic. RSC, prefetch, API and known metadata requests have injected nonce/CSP headers removed. Auth refresh forwards the updated Cookie header as well as response cookies; redirects preserve refreshed cookies. Nonce classification protects HTML detail slugs containing dots. Static Next assets/images are exempt from document generation.

Automated tests verify spoofing, matching request/response policies, fresh nonces, non-document requests, refreshed cookies and redirects. Release smoke is required in Chromium, Firefox and WebKit; the broader scheduled matrix remains. Explicit read-only public CI fixtures target only https://example.supabase.co/rest/v1/, never Auth/CAPTCHA/mail or a real Supabase endpoint. Browser checks verify real document script nonces, hydration, client navigation and blocked parser-inserted scripts. Dynamically created scripts from a trusted script are intentionally permitted by strict-dynamic, so they are not used as injection-denial evidence.

The integrated synthetic production build compiled successfully. The fixture smoke removes placeholder database retry delays and exercises the production rendering path; it is not a production latency benchmark, remote acceptance or real Turnstile verification.
